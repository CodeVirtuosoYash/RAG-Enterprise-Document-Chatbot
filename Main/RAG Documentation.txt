RAG Project

Overview
--------
This FastAPI application implements a Retrieval-Augmented Generation (RAG) pipeline using:
- BERT for document embedding
- FAISS for similarity search
- BART for answer generation
- Profanity filtering for user queries and uploaded files

Supported document formats: .txt, .docx, .pdf

File Structure Assumptions
--------------------------
All uploaded and processed documents are saved in the local folder “folder_path”.

Initialization
--------------
- BERT is used to encode documents into vector embeddings.
- FAISS is used to index and search document embeddings.
- Euclidean distance is used to calculate the distance between the embeddings of the Query and contents of a File.
- BART is used to generate final responses based on retrieved context.
- Profanity filtering is enforced using better_profanity.

Document Processing
-------------------

1. load_documents_from_folder(folder_path)
   Parses and extracts text from .txt, .docx, and .pdf files. .doc files are skipped with a warning.
   String : folder_path = stores the path to the document storage.

2. encode_documents(texts)
   Encodes a list of strings into BERT-based embeddings
   String: texts = String that have to be converted to embeddings.

3. set_up_faiss_index(documents, encode_fn)
   Creates and returns a FAISS index for the given document embeddings.
   List of Strings : documents
   


Retrieval and Generation
------------------------

1. retrieve_similar_documents(query, index, documents, encode_fn, k)
   Returns up to k most similar documents for the given query using FAISS.
2.The results are added to the final return list only if the distance between the query and document embedding is less than or equal to the threshold value (I.e 86 currently)

3. generate_answer(query, docs_with_scores, max_length=150)
   Generates a BART-based abstractive response using the retrieved documents as context.
   String : query = query given by the client
   List of Tuples : docs_with_scores = The documents Retrieved along with their distances
　　Int : max_length= Maximum number of tokens that can be generated by the LLM model.

Index Reloading
---------------
Creates new indexing incase of file addition and deletion.

reload_index()
Refreshes global variables:
- docs: document contents
- faiss_index: updated FAISS index

API Endpoints
-------------

POST /Answer
------------
Input:
  "query": "your question here"

Output (Success):
  "result": "Generated answer"

Output (Profanity):
  "result": "Query contains profanity"

Output (No Match):
  "result": "No Relevant Document Found"


POST /upload_txt
----------------
Uploads one or more .txt, .pdf, or .docx files.

- Rejects unsupported file formats.
- Filters files with profanity.
- Rebuilds index post-upload.

Input: Single or Multiple Files

Output (Unsupported File) :
	“result”: “Not a .txt / .pdf / .docx file”

Output (Profanity) :
	“result”: “File contains Profanity”

Output (Success) :
	“result”: “uploaded”

DELETE File
----------------------------------------
Deletes a file from the storage folder.

Query Param:
- filename: name of the file to delete

Output (Success):
  "message": " <filename> deleted successfully."

Output (File not Found):
  "message": "File not found."

Output (Failure):
  "message": "Error Deleting <filename> ."

Profanity Check
---------------
- On Queries: better_profanity.contains_profanity(query)
- On Uploaded Files: cleans text and checks profanity before saving.





Models Used
-----------

Model     | Purpose        | Source
-----------------|-------------------------|-------------------------------
BERT      | Embedding      | bert-base-uncased
BART      | Answer Gen     | facebook/bart-large-cnn

Requirements
------------

Install all required libraries:

pip install fastapi uvicorn torch transformers faiss-cpu python-docx pymupdf better_profanity

Running the Server
------------------

uvicorn main:app --reload

Or

python -m uvicorn <File Name>:app --reload --port <number>

Example Usage
-------------

1. Upload documents at /upload_txt
2. Query at /Answer with a user question
3. Get contextual answer from your document base
4. Remove unwanted documents using /delete_file
